# Module brief — Search + Settings panels (`CsCode.Panels.Search`)

**Owns:** `src/CsCode.Panels.Search/**`, `tests/CsCode.Panels.Search.Tests/**`, `docs/PANELS-SEARCH.md`. Read `docs/briefs/00-common.md` first (rules, threading, memory) — everything there applies.
**Context:** Platform, LSP, DAP, Editor, shell kit (`CsCode.Ui`) and shell (`CsCode.App`) are merged into your worktree's base; their agents are *still working* on their own branches in parallel. You build only these panels against Core interfaces + `CsCode.Ui`; don't edit their projects.
**Provides:** `IToolWindow`s (`CsCode.Ui.IToolWindow`) and a settings/keyboard-shortcuts *document* view, registered by `AddCsCodeSearchPanels(this IServiceCollection)`. The shell creates views lazily and **disposes them when hidden/closed**.
**Consumes (Core, via DI):** `IWorkspaceService` (`FindFilesAsync`, `FileSystem`, folders), `IFileSystem`, `IDocumentManager` (search dirty in-memory documents, not stale disk), `INavigationService` (open at a match, `ApplyWorkspaceEditAsync` for replace), `ICommandService`, `IConfigurationService` (`Properties`, `Get/GetRaw/UpdateAsync`, `Changed`, `UserSettingsPath`), `IKeybindingService` (`All`, `GetLabel`), `IStateStorage` (history), `IWindowService`, `IContextKeyService`, `Glob`.
**Design system:** `src/CsCode.Ui` (`vsc:<colorId>` brush keys via `WorkbenchColors`/`ThemeApplier`, `Icon`, `UiDispatcher`, `BulkObservableCollection`, `FuzzyMatcher`).

## MUST
### A. Search engine (`CsCode.Panels.Search.Engine`, UI-free, in this project)
Streaming, parallel, cancellable text search across the workspace folders:
* File enumeration via `IWorkspaceService.FindFilesAsync` (honours `files.exclude` + `.gitignore`), plus per-query include/exclude globs (`Glob`), "search only in open editors", "use exclude settings / ignore files" toggles.
* Matching: literal / case-sensitive / whole-word / **regex** (.NET `NonBacktracking` where possible, with a per-file match timeout so a pathological regex can't hang a worker), multi-line regex optional, **binary-file skip** (NUL sniff in the first 8 KB), encoding handling (UTF-8/UTF-16 BOM, UTF-8 default, Latin-1 fallback), **max file size** (default 5 MB; setting `search.maxFileSizeBytes`), long-line guard (matches in lines > 10k chars get a clipped preview), **dirty open documents are searched from memory** (`IDocumentManager`) not from disk.
* Execution: runs on the **IO lane / dedicated threads** (never the UI thread, never starving the shared pool): bounded parallelism (`min(processors/2, 8)`), results **streamed in batches** (≤ 16 ms windows), hard result cap (`search.maxResults` default 20,000, with a clear "results truncated" signal), **cancellation within ~10 ms** (check the token per line/chunk), progress (files scanned / matched), memory O(results), file contents streamed in 64 KB chunks (never read a whole large file into a string unless regex mode needs line-based reading).
* Replace: `ReplacePreview` (per-match old/new text, regex capture groups `$1`, case-preserving option, "preserve case"), apply via a `WorkspaceEdit` through `INavigationService.ApplyWorkspaceEditAsync` (open docs edited as undoable groups; closed files edited on disk by the navigation service) — one confirmation for multi-file replace.
### B. Find in Files tool window (`search`, Left or Bottom per `DefaultLocation = Left` — VS shows "Find in Files" as a document/tool window; provide as a tool window, bottom)
Query box with toggles (Match Case `Aa`, Whole Word `ab`, Regex `.*`), "files to include"/"files to exclude" fields with globs, **search history** (↑/↓, persisted via `IStateStorage`, capped 50), replace box + Replace All / per-file / per-match, **results tree** grouped by file (virtualised; file node: icon, name, folder path dimmed, match count badge; match node: line number + preview with match highlighted via a `TextBlock` with `Inlines`/custom render; ellipsis clipping), collapse/expand all, dismiss result (Del), keyboard navigation (↑↓, Enter opens at the match with the match selected via `INavigationService.OpenAsync(uri, range)`, F4 next result, Shift+F4 previous), summary line ("12 results in 4 files — 38 ms" / "truncated at 20,000"), live "searching…" progress, cancel button, re-run on workspace change optional, context menu (Open, Copy Path, Reveal in Explorer if a command exists, Dismiss, Replace).
Commands (register in `AddCsCodeSearchPanels` if not already registered by the shell — check `src/CsCode.App` first): `workbench.action.findInFiles` (Ctrl+Shift+F), `workbench.action.replaceInFiles` (Ctrl+Shift+H), `search.action.focusNextSearchResult` (F4), `search.action.focusPreviousSearchResult` (Shift+F4), `search.action.clearSearchResults`, `search.action.collapseSearchResults`. Seed the query from `INavigationService`'s current selection if available (additive: optional `IActiveSelectionProvider` exists in Core).
### C. Settings UI (a *document* view `settings`, opened by command `workbench.action.openSettings`; "Open Settings (JSON)" remains `workbench.action.openSettingsJson` — register it if the shell hasn't)
Search box with fuzzy filtering (`FuzzyMatcher`); left category tree from key prefixes (Editor, Files, Workbench, Memory, LSP, Debug, Vim, …); each setting rendered from `ConfigurationProperty` metadata + JSON schema (`Schema`/`Default`): bool → toggle, integer/number → numeric box with validation (min/max), string → text box, `enum` → combo with descriptions, `array`/`object` → read-only summary + **"Edit in settings.json"** link (opens the file revealed at that key); "modified" marker + gear menu **Reset Setting** / **Copy Setting ID**; **User vs Workspace** scope tabs (`ConfigurationTarget`), live updates when `IConfigurationService.Changed` fires, writes via `UpdateAsync` (comment-preserving writer), debounced edits, validation errors inline; `@modified` filter. Also a **Keyboard Shortcuts** view (`workbench.action.openGlobalKeybindings`): table of `IKeybindingService.All` (command, key label, when, source User/Default) with filter, "Open keybindings.json" button (rebinding UI is a STRETCH).

## SHOULD
Search editor-style "open results in editor", search in selection, "exclude this folder" from results context menu, search scope to a folder from Explorer (command + argument), include/exclude presets, settings sync-style export (no).

## Threading & isolation (binding — ARCHITECTURE §6)
* The UI thread only renders and applies *small immutable batches*; all scanning, regex, decoding and sorting happen on the IO lane. No sync-over-async (banned-API analyzer is on). Results appended via `UiDispatcher.PostBatched` in ≤ 4 ms slices; the tree is virtualised; counts update coalesced.
* **Hostile tests**: a synthetic tree of **200k files** (+ some multi-hundred-MB and binary files, pathological regexes like `(a+)+$`, 1M-match single file, files with 10 MB lines) — assert dispatcher heartbeat latency p99 < 16 ms / max < 50 ms during the search, cancel latency < 50 ms, result cap honoured, memory bounded (no growth proportional to files scanned), no worker left running after cancel/dispose.
* All subscriptions in `DisposableStore`s released on view disposal; `LeakAssert` after opening/closing the panel and running/cancelling 100 searches.
