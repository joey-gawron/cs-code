# Module brief — Shell (`CsCode.App` + `CsCode.Ui`)

**Owns:** `src/CsCode.App/**`, `src/CsCode.Ui/**`, `tests/CsCode.App.Tests/**`, `docs/SHELL.md`, `THIRD-PARTY-NOTICES.md`, the Avalonia/Dock items in `Directory.Packages.props` (versions pinned already).
**Implements (Core):** `IWindowService`, `IStatusBarService`, `IOutputService`, `INavigationService`; the VS2022 `ColorTheme`s (registered into `IColorThemeService`); the `IToolWindow` host (`CsCode.Ui.IToolWindow`).
**Consumes (Core, via DI):** everything — you are the composition root: `AddCsCodeCore/Platform/Lsp/Dap/Extensions/Editor/Profiling` (all exist as stubs now; the real implementations are being written **concurrently** by other agents and merged later).
**Does not touch:** other modules' projects. Panels for debugging/extensions/search/settings are a **later wave** — design the extension points (`IToolWindow`, menu/command wiring) so those drop in.

## Parallel-development reality (read this)
Platform, LSP, DAP, Extensions, Editor and Profiling are being built at the same time by other agents; **their implementations do not exist in your worktree**. Therefore:
* Program against Core interfaces only. In `tests/CsCode.App.Tests` compose the app with `CsCode.TestDoubles` fakes (`TestCommandService`, `TestConfigurationService`, `TestContextKeyService`, …) plus any minimal extra fakes **you** need (keep them in the test project, e.g. an in-memory `IKeybindingService`, `IWorkspaceService`, `IFileSystem`, `IStateStorage`). Build a `DevHost` helper that composes the real shell with these fakes — that is how you run, test and screenshot the app now.
* The composition root (`AppServices.Build(...)`) must register the real modules (`AddCsCodeX()`), and the dev/test host must be able to **replace** any service. Do not hide missing registrations with silent fallbacks in production code.
* The editor view comes from `IEditorViewFactory` — until the real editor lands you get the `PlainEditorViewFactory` TextBox stub; that is fine.

## Goal
A **Visual Studio 2022–looking** native shell (Avalonia 12 + Dock.Avalonia) that is a joy to use and memory-flat. Specification in `docs/ARCHITECTURE.md` §7 is binding; the details below add to it. Fidelity to VS2022 matters: spacing, colours, tab shapes, tool-window captions, menu look, status bar colours, iconography weight.

## MUST
### A. Design system — `CsCode.Ui`
1. **Theme pipeline**: `ThemeApplier` listens to `IColorThemeService.Changed` and (re)populates application-level resources: one `SolidColorBrush` per workbench colour id under the key **`vsc:<colorId>`** (e.g. `{DynamicResource vsc:editor.background}`, `vsc:sideBar.background`, `vsc:statusBar.background`, `vsc:list.activeSelectionBackground`, `vsc:tab.activeBackground`, `vsc:focusBorder`, `vsc:button.background`, `vsc:menu.background`, …) using the Core fallback chain for missing keys, plus `Color`/`Thickness`/`CornerRadius`/`FontFamily`/`FontSize` tokens (`ui:FontFamily`, `ui:FontSize` = 12 px VS-like, `ui:CornerRadius` = 0/2). Switching theme at runtime updates the whole UI without recreating windows. **Document the key list** the panel authors may rely on in `docs/SHELL.md` (they will code against `vsc:` keys in the next wave).
2. **Built-in VS2022 themes** as `ColorTheme` data registered at startup: **Visual Studio Dark** (editor `#1E1E1E`, tool windows `#252526`, chrome `#2D2D30`/`#333337`, borders `#3F3F46`, accent `#007ACC`, selection `#264F78`, tab active `#007ACC` top bar / `#1E1E1E`, tab inactive `#2D2D30`, menu `#333337`, status bar `#007ACC` / debugging `#CA5100` / no-folder `#68217A`, text `#F1F1F1`, subtle text `#999999`, hover `#3E3E40`, input `#333337`…), **Visual Studio Blue** (the 2022 Blue palette: `#293955` chrome, `#CFD6E5` backgrounds, …), **Visual Studio Light** (`#F5F5F5` chrome, `#FFFFFF` editor, `#CCCEDB` borders, `#007ACC` accent). Token colours for each (VS2022's C#-ish palette: keywords `#569CD6`, types `#4EC9B0`, strings `#D69D85`, comments `#57A64A`, numbers `#B5CEA8`, functions `#DCDCAA` — in Light the Visual Studio Light equivalents). Include `ThemeKind`. Default = Dark.
3. **Control library / styles** (Avalonia `ControlTheme`s/styles) giving *all* standard controls the VS look driven by the `vsc:` keys — do **not** ship the stock Fluent look: Button (flat, accent on default), ToggleButton, CheckBox, RadioButton, TextBox (VS input box: 1 px border, accent on focus), ComboBox, ListBox/ListBoxItem, TreeView/TreeViewItem (VS chevrons, row hover/selection/inactive-selection colours, indentation guides optional), TabControl, Menu/MenuItem/ContextMenu (VS flat menus with check column, icon column, shortcut column, separators, submenu arrows, `#333337` bg / accent hover), ToolTip, ScrollBar/ScrollViewer (**VS thin scrollbars** with pill thumbs that widen on hover), Expander, GridSplitter, ProgressBar (marquee + determinate), Slider, ToggleSwitch, DataGrid-lite (not required), Separator, Flyout/Popup shadows, validation errors. Fonts: `Segoe UI` if present → Inter (already embedded) fallback; code font from settings.
4. **Shared controls**: `Icon` control + catalog (Codicons font embedded as resource — CC-BY-4.0 — with the attribution in `THIRD-PARTY-NOTICES.md`; `IconKey` → glyph map for ≥ 150 icons used by the shell; HiDPI crisp; theme-coloured), `VsStatusBar`, `VsToolBar` (+ separators, split buttons, dropdowns, toggle states), `ToolWindowCaption`, `FilterBox` (search box with clear), `VirtualizedTreeView` helper if the stock `TreeView` can't virtualise your explorer needs (measure first), `InfoBar`/`Toast` (notifications), `ModalDialog` host, `QuickPickView` (the palette list: icon, label with fuzzy-match highlighting spans, description, detail, keybinding label, separators, multi-select), keyboard-first behaviours (type to filter, ↑↓, Enter, Esc, Tab).
5. **Dock theme**: restyle Dock.Avalonia (document tabs, tool tabs, tool-window caption/pin/close buttons, splitters, drop-target indicators, float windows) to the VS2022 look: document tab strip with the **coloured top accent on the active tab**, preview tabs in *italic*, dirty dot that becomes ✕ on hover, pinned tabs, overflow chevron list; tool windows with caption bars and dropdown (“Dock / Float / Auto Hide / Hide”), auto-hide side bars with rotated labels. Dock.Avalonia 12.1.0.13 is the library; study its API (decompile/XML docs) and its theme resource keys.
### B. Shell — `CsCode.App`
6. **Composition root & startup**: `Program` → `AppServices.Build(args)`; CLI (`cscode [paths…]`, `--new-window`, `--wait` ignored, `--list-extensions` optional); structured crash handler (unhandled exceptions → log file + friendly dialog, never silent exit); single-instance forwarding (SHOULD); **fast first paint** — show the window before heavy services init; defer extension discovery/LSP start until after first frame (`Dispatcher.UIThread.Post` at `Background` priority, then `IExtensionService.ActivateByEventAsync("onStartupFinished")`); high-DPI; app icon (original artwork you create as SVG→PNG at build time or embedded; **no Microsoft/VS trademark logos**).
7. **Service implementations**: `WindowService` (non-modal notification toasts with action buttons + a notification centre list, quick pick/input box overlays (Command-Palette-style, not OS dialogs), native open/save dialogs via `StorageProvider`, progress in the status bar + notification, `OpenExternalAsync`, clipboard), `StatusBarService` (+ items for Ln/Col, indent, encoding, EOL, language mode picker, diagnostics counts, memory, debug state, server status), `OutputService` (bounded 2 MB ring per channel, channel dropdown, append batching on the UI thread — never one dispatcher post per line), `NavigationService` (open/reveal/preview tabs, selection reveal, **`ApplyWorkspaceEditAsync`**: open docs edited as one undo group each; closed files edited on disk via `IFileSystem` after reading; create/rename/delete resource operations; confirmation dialog for multi-file edits), active document/caret tracking.
8. **Chrome**: custom title bar (app icon, menu bar, centred **Quick Launch** box (Ctrl+Q) which opens the palette, window controls; native decorations fallback when the platform lacks custom chrome; Linux: draggable, double-click maximise, snap-friendly), standard toolbar (VS2022 layout; launch-configuration combo bound to `IDebugConfigurationService` **if resolvable**, green Start ▶ button with dropdown, step buttons visible only while debugging — wire to `KnownCommands.Debug*`), status bar with the state colours from §7.
9. **Menus**: **File, Edit, View, Go, Debug, Terminal, Tools, Extensions, Window, Help** exactly populated with the standard VS commands (use `KnownCommands`/VS Code command ids), each item bound to `ICommandService.ExecuteAsync`, enablement from `IContextKeyService.Evaluate(when)`, shortcut labels from `IKeybindingService.GetLabel`, check state where relevant (View > tool windows), recent files/folders submenu, dynamic contributed items from `IContributionRegistry.Of<MenuContribution>()` for `commandPalette`, `editor/context`, `explorer/context`, `editor/title` (+ their `when`), **native menu bar** (`NativeMenu`) on macOS and where DBus global menus exist; fully keyboard accessible (Alt mnemonics, arrow navigation).
10. **Keyboard pipeline**: window-level tunnelling handler converts key events → `KeyStroke` (VS Code names), consults `IKeybindingService.Resolve`; `Matched` → execute command (+args), `Pending` → swallow and show "(Ctrl+K) was pressed. Waiting for second key of chord…" in the status bar, `None` → let the focused control handle it (editor typing); chord timeout/Esc reset; **context keys maintained** in `IContextKeyService`: `editorTextFocus`, `editorHasSelection`, `editorReadonly`, `editorLangId`, `resourceExtname`, `resourceFilename`, `resourceScheme`, `explorerViewletFocus`, `listFocus`, `panelFocus`, `inputFocus`, `terminalFocus`, `inDebugMode`/`debugState` (from `IDebugService`), `isMac/isLinux/isWindows`, `workspaceFolderCount`, `hasOpenEditors`, `activeEditorIsDirty`, `quickInputVisible`, `config.*` handled by Platform.
11. **Docking & documents** (Dock.Avalonia): central document well (tab management: open/preview/pin/close/close-others/close-saved/close-all, **dirty-state prompts** (Save/Don't Save/Cancel), reopen closed, drag-reorder, split right/down + move between groups, Ctrl+Tab MRU switcher overlay), tool windows (Explorer, Output, Error List, Find Results, plus any `IToolWindow` in DI) docked per `DefaultLocation`, auto-hide, float, tab-group; **layout persisted** per workspace + global defaults (`IStateStorage`), restored on start, "Reset window layout" command; per-tab editor views created via `IEditorViewFactory.CreateView(doc)`; **memory policy**: only the active tab of each group (+ LRU of `cscode.shell.liveEditorViews` default 8) keeps a live view — others are disposed and later recreated from saved view state (`IEditorViewController` view-state API if available at integration time; until then keep a stub hook).
12. **Explorer** (`IToolWindow`): lazy, **virtualised** tree (10k+ files fine), VS-style file icons by extension (a built-in icon set; extension icon themes later), expand state persisted, create/rename (F2, inline editor)/delete (trash)/duplicate/cut/copy/paste/drag-and-drop move, reveal active file, `files.exclude` honoured, live refresh through `IFileWatcher` (batch updates; never rebuild the whole tree), keyboard navigation incl. type-ahead, context menu (contributed items too), "Open Folder" empty-state, filter box, multiple root folders. Folder open via native dialog, command line, drag-drop onto window, recents.
13. **Output**, **Error List** (`IDiagnosticService` grouped/sorted by file/severity/source, filter chips for Errors/Warnings/Info with counts, search box, double-click navigates via `INavigationService`, virtualised — 50k rows OK, throttled updates ≤ 10 Hz), **Find Results** (hosts results delivered via the `cscode.references.show` command: locations with preview line text read lazily).
14. **Command palette / Quick Launch** (`QuickPickView` overlay): modes by prefix — plain = go to file (`IWorkspaceService.FindFilesAsync` + Platform `FuzzyMatcher` if present, else a local matcher), `>` commands (title, category, keybinding, recently used first), `:` go to line, `@` document symbols (`IDocumentSymbolProvider`), `#` workspace symbols (`IWorkspaceSymbolProvider`), `?` help; async sources with cancellation; fuzzy highlight; instant open (< 50 ms to first paint after Ctrl+Shift+P); also drives `IWindowService.ShowQuickPickAsync/ShowInputBoxAsync`.
15. **Welcome / Start page** tab (VS2022 "Start window" inspired: recent folders & files, Open Folder, New File, links) shown when no folder is open; **About** dialog with versions, runtime info, third-party notices; **Settings**: `Open Settings (JSON)` opens the settings file in the editor (a settings *UI* is a later-wave panel).
16. **Theme command** `workbench.action.selectTheme` (quick pick of `IColorThemeService.Available` with live preview on arrow-key navigation and revert on Esc); `View > Appearance` toggles.
17. **Memory instrumentation hooks**: status-bar memory item reading `IMemoryMonitor` when present; tool-window views are **disposed when hidden** (`IToolWindow.CreateView` contract), tab/view LRU as above; no dispatcher floods; all subscriptions in `DisposableStore`s owned by view-models/views and disposed on close; UI collections use batched `ObservableCollection` updates or `DataGridCollectionView`-style bulk replace.

## SHOULD
Auto-hide/peek animations, jump list/recent on taskbar, zen mode, full-screen, status-bar items from extensions (`IStatusBarService`), toolbar overflow, high-contrast theme, window title with dirty marker/`●` and workspace name, `--diff` two-file compare (SHOULD be skipped unless the editor supports it), "Go to Definition/References/…" entries in editor context menu, drag a file onto the window to open, per-monitor DPI, keyboard shortcut reference page (generated from `IKeybindingService.All`).
