# Module brief — Remote editing (`CsCode.Remote` + `CsCode.Server`) — **wave 2** (needs the merged Platform/LSP/DAP/Editor/Shell)

**Owns (when launched):** `src/CsCode.Remote/**` (client library, Avalonia-free), `src/CsCode.Server/**` (headless executable `cscode-server`), `tests/CsCode.Remote.Tests/**`, `tools/publish-server.sh`, `docs/REMOTE.md`, additive Platform/Core/Shell glue as listed below, the *Remote* section of `Directory.Packages.props`.

## Assumed meaning of "remote editor support" (flag to user if wrong)
**VS Code Remote-SSH style**: the GUI runs locally; the *workspace* — files, search, file watching, language servers, debug adapters, tasks, terminal — lives on a remote machine, reached over SSH. (Also designed to serve WSL / Docker / `kubectl exec` later via the same transport abstraction.) Real-time collaborative editing is **not** included.

## Architecture
```
 CsCode.App (GUI, local) ── CsCode.Remote (client) ── IRemoteTransport ──► ssh -T host cscode-server --stdio ──► CsCode.Server (headless, remote)
                                    │  RemoteFileSystem (ssh: scheme) ·  provider/diagnostic/debug bridges ·  settings mirror          │ composes Platform + Lsp + Dap services
                                    ▼                                                                                              ▼ language servers, debug adapters, files, search, tasks, terminal run HERE
```
* **Transport** (`IRemoteTransport`): `SshTransport` using the **system `ssh` binary** (honours `~/.ssh/config`: ProxyJump, IdentityFile, ControlMaster, agent, 2FA; `ssh -G <host>` to resolve effective settings; `-T -o ServerAliveInterval=15 -o ExitOnForwardFailure=yes`), `LoopbackTransport` (spawns `cscode-server` locally over stdio — used by tests AND by the **local process-isolation mode** `cscode.languageHost=process`, which gives the language client its own heap/GC/CPU scheduling), stretch: `WslTransport`, `DockerExecTransport`. All transports expose a duplex byte stream + lifecycle; a `ChaosStream` test wrapper injects latency/drops/disconnects.
* **Protocol**: JSON-RPC 2.0, `Content-Length` framing (StreamJsonRpc + System.Text.Json), typed service interfaces mirroring Core (`IRemoteFileSystem`, `IRemoteWatcher`, `IRemoteSearch`, `IRemoteLanguageHost`, `IRemoteDebugHost`, `IRemoteTasks`, `IRemoteTerminal`, `IRemoteWorkspace`, `IRemoteDocuments`) + version/capability handshake; large payloads chunked (256 KB) with optional compression; every call cancellable with timeouts; bounded server-side queues. Documented in `docs/REMOTE.md`.
* **Server bootstrap** (`ServerInstaller`): detect remote OS/arch (`uname -sm` / `cmd /c ver`), look for `~/.cscode-server/bin/<buildhash>/cscode-server`; if absent upload the matching bundle (built by `tools/publish-server.sh`: `dotnet publish -r <rid> --self-contained -p:PublishSingleFile=true`, trimmed where safe — use source-generated JSON contexts; fall back to framework-dependent when the remote has a compatible runtime) **streamed over the ssh channel** (tar|gzip over stdin, sha256 verified, atomic rename, `chmod +x`), cached by hash, cleaned up (keep last 2). Never run remote shell strings built by concatenation: fixed commands + stdin payloads; quote/escape via a tested arg builder (fuzz-tested against `; $() \` ' " & | newline`).
* **Auth UX**: ssh prompts (passphrase, password, 2FA, host-key confirmation) are routed through `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force` to a tiny helper mode of the app (`cscode --askpass "<prompt>"`) that talks to the running GUI over a **local, owner-only, one-time-token** socket and shows the prompt through `IWindowService`. **Never read `~/.ssh/*` keys or the real known_hosts yourself; never store secrets.**
* **Client services**: `RemoteConnectionManager` (new additive Core contract `IRemoteConnectionManager`: connect/disconnect/reconnect, state machine `Disconnected→Connecting→Bootstrapping→Connected→Reconnecting→Failed`, `Status`, events), `RemoteFileSystem` as the provider for scheme **`ssh://[user@]host[:port]/abs/path`** (needs the **additive Platform change**: a routing `IFileSystem` that dispatches by scheme to `IFileSystemProvider`s — `LocalFileSystem` becomes the `file:` provider; implement `FileSystemRouter` in Platform's own new files), remote atomic writes (server-side temp+rename), mtime/size etag conflict detection, directory-listing cache invalidated by remote watcher events (bounded, `IMemoryTrimmable`), content prefetch for open tabs, request batching/pipelining, `RemoteWatcher`, `RemoteSearch` (server-side parallel search streaming results — Find in Files and quick-open run **on the remote**), remote workspace folder via `IWorkspaceService`.
* **Language/debug bridging**: the server hosts the real `ILanguageServerManager`, `IDebugService`, `ITaskService` against remote files. Client side registers **bridge providers** in the local `ILanguageFeatureRegistry` for documents with remote URIs (forwarding each provider call, mapping Core models over the wire — the Core models are already JSON-friendly records), mirrors `IDiagnosticService` and server-originated UI requests (`IWindowService` messages/progress/quick-picks, `INavigationService` opens, `workspace/applyEdit`) back to the GUI; open documents sync local→remote through `IDocumentManager` events (full text on connect/reconnect, incremental afterwards); the debug UI binds to a client `IDebugService` that proxies remote sessions (and keeps local ones) — breakpoints/settings sync. `IConfigurationService`: user settings flow client→server; workspace settings read on the server.
* **Resilience**: auto-reconnect with backoff + jitter; editor stays usable while disconnected (clear UI state; saves queue; conflict resolution on reconnect); server may outlive a dropped client for a grace period (stretch: reattach to running LSP/debug sessions); heartbeat; clean teardown (no zombie `ssh`/server processes).
* **Threading/isolation (binding, ARCHITECTURE §6)**: the connection reader/writer and all remote calls run on a dedicated **Remote lane**; the UI thread never waits on the network (all async, cancellable, coalesced, with timeouts); remote results arrive as immutable batches; hostile-network tests (500 ms RTT, 5 % loss/reset, bandwidth cap, mid-request disconnect, server hang) must not affect UI dispatcher latency or typing latency budgets.
* **UI glue (Shell, additive files)**: File ▸ *Open Remote Folder…* and palette `Remote: Connect to Host…` (hosts parsed from `~/.ssh/config` `Host` entries without wildcards + "Add new host"), blue/green/orange/red **remote indicator** at the left of the status bar with host + state, connection-progress notification with *Show Log* (Output channel "Remote"), `cscode ssh://host/path` CLI, disconnect/reconnect/reinstall-server commands, per-host settings (`remote.ssh.*`), remote icon overlay in Explorer title.

## Tests (`tests/CsCode.Remote.Tests`)
* Unit: protocol codec round trips for every Core model, URI ⇄ path mapping (spaces, `#`, `%`, IPv6 hosts, ports, Windows remotes), ssh arg builder **injection fuzz**, `ssh -G` output parser, ssh-config host listing, installer decision logic, reconnect state machine with a fake clock.
* **Loopback integration** (server as a local child process): the *whole* stack through the client — open/edit/save files, watcher events, search, real `typescript-language-server` diagnostics/completion/hover through the bridge, real `netcoredbg` debug session through the proxy, tasks.
* **Real SSH** (`ssh` client is present; `sshd` is not): obtain `sshd` into `.scratch/tools` (try `nix shell nixpkgs#openssh -c …` / `nix build nixpkgs#openssh` — it is a user-level, non-destructive operation; else skip with a clear reason), generate **throwaway** host/user keys in a temp dir, run `sshd -D -e -f <tmp sshd_config> -p <ephemeral>` as the current user (`UsePAM no`, `StrictModes no`, `PasswordAuthentication no`, `AuthorizedKeysFile` in temp), and connect with `ssh -F <tmp ssh_config> -i <tmp key> -o UserKnownHostsFile=<tmp>`: full bootstrap (upload + start server) + file ops + LSP smoke. **Never touch `~/.ssh` or the user's real agent/known_hosts.**
* Chaos (latency/drops/disconnect/hang) incl. UI-responsiveness assertions with the Profiling `ResponsivenessProbe`; connect/disconnect ×50 leak/zombie checks (`LeakAssert`, process/thread/fd counts); bounded memory for caches; server shutdown leaves no children.
