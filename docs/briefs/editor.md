# Module brief — Editor (`CsCode.Editor`)

**Owns:** `src/CsCode.Editor/**`, `tests/CsCode.Editor.Tests/**`, `docs/EDITOR.md`, the *UI: Avalonia / Editor* items you add in `Directory.Packages.props` (the Avalonia/AvaloniaEdit/TextMate/Dock versions are already pinned — don't bump without proving it builds).
**Implements:** `IEditorViewFactory`/`IEditorViewController` (replace `PlainEditorViewFactory`, keep the interfaces; you may ADD members), `IEditorDocument` over AvaloniaEdit's rope, Core `ILanguageService`, Core `IColorThemeService`, snippet engine, language-feature UI.
**Consumes (Core, via DI):** `IDocumentManager`, `ILanguageFeatureRegistry`, `IDiagnosticService`, `IContributionRegistry` (languages/grammars/themes/snippets), `IConfigurationService`, `IFileSystem`, `IFileWatcher`, `IWindowService`, `INavigationService`, `ICommandService`, `IContextKeyService`, optional `IEditorConfigService` (if Platform ships it), optional `IDebugService` + `IBreakpointManager` (breakpoint gutter, stop line, hover-evaluate), optional `IMemoryMonitor`, `ILoggerFactory`.
**Does not touch:** the shell (`CsCode.App`/`CsCode.Ui`), LSP/DAP/Extensions modules. You never reference them — only Core interfaces.

## Goal
A fast, correct, memory-flat code editing surface: AvaloniaEdit (`Avalonia.AvaloniaEdit` 12.0.0) + TextMate (`AvaloniaEdit.TextMate`, `TextMateSharp`) wired to the Core contracts, with VS-quality language-feature UX (IntelliSense popup, diagnostics squiggles, hover, signature help, quick actions, folding, breakpoints). Pin your API discoveries about AvaloniaEdit 12 / TextMateSharp 2.0.3 in `docs/EDITOR.md` — these versions are new; read the package XML docs / decompile when unsure rather than guessing.

## MUST
1. **`EditorDocument : IEditorDocument`** wrapping `AvaloniaEdit.Document.TextDocument` (rope). Exact mapping of document changes to `TextDocumentChangedEventArgs` (ranges expressed against the pre-change state; sequential semantics; version bump; one event per undo group/atomic operation — hook `Changing`/`Changed`/`UpdateFinished` correctly; **fuzz test** against `InMemoryTextDocument` as oracle). Position ⇄ offset helpers (AvaloniaEdit is 1-based line/column; Core is 0-based UTF-16). Dirty tracking via the undo stack's original-file marker, `ApplyEdits` as ONE undo unit, undo stack size limit (default 1000 groups, `cscode.editor.undoLimit`), thread-safe reads (snapshot via `CreateSnapshot`) for background consumers.
   Load/save through `IFileSystem` (**atomic**); **encoding detection** (BOM; UTF-8 default; UTF-16 LE/BE; fallback Windows-1252/Latin-1; `files.encoding` + preserve on save), **EOL detection & preservation** (LF/CRLF/CR, mixed → majority; status via `EndOfLine`), final-newline & trim-whitespace policies from `.editorconfig` when available; `ReloadAsync`; external-change watching via `IFileWatcher` with conflict UX through `IWindowService` ("File changed on disk — Reload / Keep") when dirty, silent reload when clean; read-only files; untitled buffers (`untitled:` scheme, Save As); registers with `IDocumentManager` on open and disposes registration on close; `Saved`/`DirtyChanged` events; `IDocumentManager.NotifySaved` after save.
   **Large-file mode**: above `cscode.editor.largeFileThresholdBytes` (default 5 MB) or very long lines (> 20k chars): language forced to `plaintext`, no tokenisation/folding/squiggles/bracket-matching, status says so; files > 200 MB refuse with a clear message. Open of a 50 MB file must stay responsive (budget in tests).
2. **`EditorViewFactory : IEditorViewFactory`** + `CodeEditorControl` (Avalonia `UserControl` hosting AvaloniaEdit `TextEditor`): multiple views per document (split); `IEditorViewController` fully working (caret, selections, reveal, focus, undo/redo, find UI, format, debug-stop line, events); **view state** capture/restore (scroll, caret, selection, folds) so the shell can destroy and recreate views of inactive tabs to keep memory flat (`EditorViewState GetViewState()` / `RestoreViewState(...)` additive members). Disposal of a view unhooks *every* handler/renderer/transformer/margin it added (**leak test**).
3. **Settings-driven rendering** (live, via `IConfigurationService.Changed`): font family/size/ligatures off by default, `editor.tabSize`, `editor.insertSpaces`, `editor.wordWrap`, `editor.renderWhitespace`, `editor.lineNumbers`, `editor.rulers`, `editor.cursorStyle`/`cursorBlinking`, `editor.smoothScrolling`, `editor.mouseWheelZoom`, `editor.bracketPairColorization.enabled`, indentation guides, current-line highlight, VS-style caret/selection/line-number gutter, EOL/whitespace glyphs, word-based selection colours; per-language overrides if Platform exposes them.
4. **TextMate syntax highlighting** via `AvaloniaEdit.TextMate`: a `IRegistryOptions` implementation backed by `IContributionRegistry` (`GrammarContribution`, `ColorThemeContribution`, `LanguageContribution`) **plus built-in grammars** from `TextMateSharp.Grammars`; embedded languages (markdown fences, HTML script/style) via `EmbeddedLanguages`/injections; grammar/theme changes apply live; per-document `TextMateInstallation` disposed with the view. **Memory**: tokenizer state is the classic hog — measure bytes per 1 MB of source, cap it (don't tokenise beyond N lines ahead for huge files, release state for views that are gone, make it `IMemoryTrimmable`), document numbers in `docs/EDITOR.md`.
5. **`LanguageService : ILanguageService`**: detection by filename pattern → extension → first-line regex (`LanguageContribution`s, built-ins for ~40 common languages), `language-configuration.json` parser (JSONC; comments, brackets, `autoClosingPairs` incl. `notIn`, `surroundingPairs`, `wordPattern` (string or `{pattern,flags}`), `folding.markers`, `indentationRules`, `onEnterRules`, `offSide`), live updates when contributions change.
6. **`ColorThemeService : IColorThemeService`** + **VS Code theme loader**: parse theme JSON/JSONC (`include` chains, `colors`, `tokenColors` (scope string with commas or arrays; settings), `semanticTokenColors`, `type` light/dark/hc), convert to `ColorTheme`; fallback chain for ~150 workbench/editor color keys (embed the defaults table for dark/light so a theme that omits keys still looks right); persist selection in `workbench.colorTheme`; apply editor colors (background/foreground, selection, inactive selection, line highlight, whitespace, rulers, indent guides, bracket match, find match, squiggles, gutter) and the TextMate theme; `Register` for shell-provided themes (the shell registers VS2022 Dark/Blue/Light). Ship Dark+/Light+ equivalents built in.
7. **Editing behaviours** (each as `ICommandService` commands using VS Code ids, registered in `AddCsCodeEditor`): auto-indent (language configuration + `.editorconfig`), auto-close/over-type brackets & quotes (respect `notIn` and TextMate token types for string/comment), surround-selection, toggle line comment / block comment (`editor.action.commentLine`, `editor.action.blockComment`), move line up/down, duplicate line (`editor.action.copyLinesDownAction`), delete line, indent/outdent, join lines, transpose, trim trailing whitespace, sort lines, expand/shrink selection (uses `ISelectionRangeProvider` if present else a word/line/block heuristic), go to line, `editor.action.triggerSuggest`, `triggerParameterHints`, `quickFix`, `revealDefinition`, `goToReferences`, `rename`, `formatDocument`, `formatSelection`, `organizeImports` (via code action kind), `editor.fold*`/`unfold*`, `toggleFold`. Format on save (`editor.formatOnSave`) + on type + on paste (setting-gated) via `IDocumentFormattingProvider`.
8. **Snippet engine** (`CsCode.Editor.Snippets`): full VS Code syntax — `$1`, `${1:default}`, nested placeholders, `${1|a,b,c|}` choices, `$0`, mirrors/linked tab stops, variables (`TM_FILENAME`, `TM_FILENAME_BASE`, `TM_DIRECTORY`, `TM_FILEPATH`, `TM_LINE_INDEX`, `TM_LINE_NUMBER`, `TM_SELECTED_TEXT`, `TM_CURRENT_LINE`, `TM_CURRENT_WORD`, `CLIPBOARD`, `RELATIVE_FILEPATH`, `CURRENT_YEAR…SECOND`, `UUID`, `RANDOM`, `BLOCK_COMMENT_START/END`, `LINE_COMMENT`, `WORKSPACE_NAME`), transforms `${var/regex/format/flags}`, indentation normalisation, Tab/Shift+Tab navigation with highlighted placeholders, Esc to exit. Used by completion (`InsertTextFormat.Snippet`) and snippet files (`SnippetContribution` + user snippets `~/…/snippets/<lang>.json`, prefix completion). **≥ 60 unit tests** incl. every grammar corner.
9. **IntelliSense UI wired to `ILanguageFeatureRegistry`** (all requests cancellable, debounced, stale-result safe — never show results for an older document version/caret):
   * **Completion popup** (VS-IntelliSense look: kind icon column drawn from an icon font/geometry set you embed (Codicon licence CC-BY-4.0 — add attribution to `THIRD-PARTY-NOTICES.md`), label + detail, right-hand documentation panel with Markdown, fuzzy filter/sort using `sortText/filterText/preselect`, commit characters, `isIncomplete` re-query, `resolve` on selection, `textEdit`/`additionalTextEdits`, snippet insertion, quick suggestions while typing identifiers (`editor.quickSuggestions`), trigger characters, Ctrl+Space; merges results from several providers by score).
   * **Hover** (dwell ≈ 300 ms; Markdown → rich text: paragraphs, inline/fenced code with TextMate colours when possible, links, bold/italic, lists; merged from all providers; also shows diagnostic message + quick-fix link under the squiggle), **signature help** popup (active parameter bolded, overload cycling with ↑/↓, retrigger on `,` and `)`), **diagnostics**: squiggles in 4 severities (wavy `IBackgroundRenderer`, theme colours `editorError.foreground` etc.), tooltips, overview markers on the scrollbar (SHOULD), `Hint`/`Unnecessary` faded text, **lightbulb** (Ctrl+. menu from `ICodeActionProvider`, preferred actions, kinds; executes edits via `INavigationService.ApplyWorkspaceEditAsync` and commands via `ICommandService`), **go to definition** (F12, Ctrl+Click with underline, Alt+F12 peek = SHOULD), **find references** (Shift+F12 → single result navigates; many → `IWindowService.ShowQuickPickAsync` list as the MVP presenter and fire command `cscode.references.show` with locations as an extension point for the shell's Find Results), **rename** (F2: prepareRename → `IWindowService.ShowInputBoxAsync` → `ApplyWorkspaceEditAsync`), **document highlights** (occurrences of the symbol under caret), **folding** (indentation-based + language-configuration markers + `IFoldingRangeProvider`, VS-style +/- glyphs, collapsed-region hover), bracket matching + (setting-gated) bracket pair colourisation, **inlay hints** and **code lens** (SHOULD), **semantic tokens** overlay on top of TextMate (SHOULD).
10. **Debug integration (only through Core, all null-safe when no debugger is registered)**: breakpoint **glyph margin** (click toggles via `IBreakpointManager`; right-click: conditional/hit count/logpoint editors via `IWindowService.ShowInputBoxAsync`; red filled = verified, hollow/grey = disabled or unverified, with tooltips from `DebugBreakpointStatus.Message`), hover-over-line ghost dot, **current execution line**: yellow arrow + line highlight driven by `IDebugService.StopLocation`/`SetDebugStopLine`, auto-reveal on stop; breakpoints **follow edits** (call `IBreakpointManager.ApplyLineShift` from document change events); **hover evaluate** while stopped (`EvaluateAsync(expr, frameId, "hover")` for the identifier/selection under the pointer; result tooltip with type/value).
11. `AddCsCodeEditor(this IServiceCollection)` registers everything; module `docs/EDITOR.md` (API discoveries, perf & memory numbers, known gaps).

## SHOULD / STRETCH
* SHOULD: minimap (cheap, optional, off for large files), sticky scroll, breadcrumbs data provider (document symbol path for the caret → exposed as `IEditorViewController.GetBreadcrumbs()`), Ctrl+click on URLs, drag-drop text, bidirectional text sanity, IME composition correctness, accessibility names.
* STRETCH: **multi-cursor** (Alt+Click / Ctrl+Alt+Up/Down / Ctrl+D next occurrence). AvaloniaEdit has no native multi-caret; if you attempt it, isolate it and be explicit about limitations; if not done, say so plainly in `docs/EDITOR.md` and the report — do not fake it. Diff editor, inline blame, color decorators.

## Tests (`tests/CsCode.Editor.Tests`, Avalonia.Headless.XUnit; the headless harness already exists — extend `TestApp` with your styles)
* **EditorDocument fuzz** (10k random edit sequences incl. CRLF/surrogates/undo/redo vs `InMemoryTextDocument`): text equality, change-event replay equality, version monotonicity, undo grouping.
* Encoding/EOL golden tests (BOMs, invalid UTF-8 fallback, mixed EOL), atomic save, external-change handling (real temp files + real `FileSystemWatcher` or the Platform watcher if available).
* Language configuration + theme loader on **real** VS Code JSON (embed small real samples: Dark+ excerpt with `include`, a Monokai-style theme, TypeScript/Python/C# `language-configuration.json`), color fallback chain, scope-selector matching specificity.
* TextMate: tokenise a real C#, TypeScript, JSON and Markdown snippet and assert scopes (golden); embedded-language fence.
* Snippet engine ≥ 60 tests; editing commands (comment toggle per language, auto-close, auto-indent, surround, move/duplicate lines).
* **Headless UI** tests: type into the control with simulated key/text input; completion popup appears from a fake `ICompletionProvider`, filters, commits (also snippet commit); hover appears from a fake provider; squiggles rendered for fake diagnostics (inspect renderer output or captured frame pixels); breakpoint margin toggles `IBreakpointManager`; folding collapse/expand; format-on-save; rename flow with `RecordingWindowService`; stale-result suppression.
* **Screenshots** of a representative editor (C# code, squiggles, popup, breakpoint, folded region) in dark and light via `CaptureRenderedFrame` saved to `.scratch/screenshots/` (git-ignored) so a human/agent can inspect them; look at them yourself (Read the PNG) and fix visual defects.
* **Perf/memory tests**: open 1 MB / 10 MB / 50 MB files (time + `GC.GetTotalMemory`), steady-state typing allocation (assert bytes/keystroke below a generous bound), tokenizer memory per MB documented; **leak tests** — open/close 500 documents+views (and recreate-from-view-state 500×) with `LeakAssert`; a view must retain nothing after disposal.
