# Module brief — DAP (`CsCode.Dap`)

**Owns:** `src/CsCode.Dap/**`, `tests/CsCode.Dap.Tests/**`, `tools/fetch-netcoredbg.sh`, `docs/DAP.md`, the *DAP* section of `Directory.Packages.props`, and (additive) `src/CsCode.Core/Tasks/**` if you add a task-service contract.
**Implements (Core):** `IDebugService`, `IDebugSession`, `IBreakpointManager`, `IDebugConfigurationService` (see `Core/Debugging/*`).
**Consumes (Core, via DI):** `IConfigurationService`, `IWorkspaceService`, `IStateStorage` (persist breakpoints per workspace), `IWindowService`, `IOutputService`, `ICommandService` (for `${command:…}`), `IContributionRegistry` (`DebuggerContribution`, `BreakpointLanguageContribution`), `IDocumentManager`, `IAppPaths`, `ILoggerFactory`, optional `IMemoryMonitor`.
**Does not touch:** Avalonia/UI, other modules.

## Goal
A complete Debug Adapter Protocol client + the services a VS-style debugger UI binds to, with a **working out-of-the-box .NET debugging story** through Samsung **netcoredbg** (MIT) — *not* vsdbg (its licence forbids use outside Microsoft products).

## MUST
1. **Protocol** (`CsCode.Dap.Protocol`, System.Text.Json, no Newtonsoft). Either generate C# models from the official schema
   (`https://raw.githubusercontent.com/microsoft/debug-adapter-protocol/gh-pages/debugAdapterProtocol.json`; commit generated output + generator under `tools/`) or hand-write the complete set for the requests/events/types you implement. Tolerate unknown fields/enum values.
2. **Transport & client** — `DebugAdapterClient`: Content-Length framing over (a) child-process stdio (`DebugAdapterExecutable`), (b) TCP (`DebugAdapterServer`), (c) named pipe/unix socket (`DebugAdapterNamedPipe`); own sequence numbering and request/response correlation (DAP is not JSON-RPC, don't force StreamJsonRpc);
   events as typed `Emitter`s; request timeouts + cancellation; **reverse requests**: `runInTerminal` (spawn the debuggee yourself for kind `integrated`/`external` — no terminal UI exists yet — wiring stdio to the Debug Console output; return `processId`), `startDebugging` (child session, `Parent` set), `progressStart/Update/End` events; child process lifecycle never leaves zombies.
3. **`DebugSession : IDebugSession`** — correct ordering per spec: `initialize` (advertise supported client capabilities honestly: `linesStartAt1`, `columnsStartAt1`, `supportsVariableType`, `supportsRunInTerminalRequest`, `supportsStartDebuggingRequest`, `supportsProgressReporting`, `supportsInvalidatedEvent`, `supportsMemoryReferences`…) → `launch`/`attach` (pass the **whole** resolved launch object through; `noDebug`) → wait `initialized` event → send all breakpoints → `configurationDone` → run. Handle `stopped` (incl. `allThreadsStopped`, `hitBreakpointIds`, exceptions → fetch `exceptionInfo` when supported), `continued`, `thread`, `output` (categories console/stdout/stderr/important/telemetry; `group`), `breakpoint` (changed/new/removed), `terminated`, `exited`, `invalidated`, `capabilities`, `loadedSource`, `module`.
   Convert 1-based ⇄ 0-based per `linesStartAt1`/`columnsStartAt1` so `Core` models are always 0-based. State machine `Initializing → Running ⇄ Stopped → Terminated` with `StateChanged`; `FocusedThreadId`.
   API behaviour: threads, stack trace (lazy paging with `startFrame/levels`), scopes, variables (paging for indexed/named children, `variablesReference` handles **invalidated on resume** — cache bounded, cleared on `continued`/step), evaluate (contexts `watch|repl|hover|clipboard`), setVariable/setExpression, completions, continue/next/stepIn/stepOut/pause (+`granularity`, `singleThread`), restart (adapter `restart` request if supported else terminate+relaunch with the same config), `StopAsync` (graceful: `terminate` if supported then wait; else `disconnect{terminateDebuggee: launch}`; hard kill after timeout), `CustomRequestAsync`, `disassemble`/`readMemory` optional.
   Source handling: `DebugSource.Path` mapped to `Uri`; `sourceReference` sources fetched via `source` request into a read-only virtual document URI `debug:/<session>/<ref>/<name>` — expose via an additive Core helper if needed.
4. **`BreakpointManager : IBreakpointManager`** — source (line/column, condition, hitCondition, logMessage → `logMessage` for adapters that support logpoints), function, exception filters (set from the active adapter's `exceptionBreakpointFilters`), enable/disable, persisted per workspace in `IStateStorage` (debounced), **`ApplyLineShift`** (the editor calls it when lines are inserted/removed so breakpoints follow edits), verification statuses from adapters (verified / moved line / message), `Changed` events with affected uris. **Session mirroring:** on any change (debounced ~50 ms) re-send the full per-file `setBreakpoints` (DAP semantics: replace-all per source) to every live session; only to sessions that support the kind; per-session status mapping back by breakpoint id.
5. **`DebugService : IDebugService`** — multi-session registry, `ActiveSession`, aggregate `DebugState`, `StopLocation` (+ events) derived from the focused session's top frame on `stopped` (and updated when the UI selects another frame via an additive API `SetFocusedFrame(sessionId, threadId, frameId)` on `IDebugService`'s implementation + Core if needed), watch expressions (re-evaluated by the UI), output aggregation (`Output` event for the Debug Console, bounded history ≤ 5,000 lines kept for late subscribers),
   `StartAsync(config)`: resolve variables → run `IDebugConfigurationProvider.ResolveAsync` → run `preLaunchTask` (see Tasks) → find the adapter via registered `IDebugAdapterFactory` for `config.Type` (extension `DebuggerContribution` → executable factory built from `program`/`runtime`/`args`/platform-specific entries; built-in netcoredbg for `coreclr`/`netcoredbg`) → create session; `StopAllAsync`; clean shutdown of every session + adapter process on dispose. Sets the context keys **if** `IContextKeyService` is resolvable: `debugState`, `inDebugMode`, `debugType`, `debuggerAvailable`, `focusedSessionIsAttach`, `breakpointsExist`.
6. **`DebugConfigurationService`** — loads `launch.json` (JSONC; `.cscode/launch.json` first, then `.vscode/launch.json`; `configurations[]`, `compounds[]` with `stopAll`/`preLaunchTask`, `inputs[]`); watches for changes; `Selected` persisted; **variable substitution**: `${workspaceFolder}`, `${workspaceFolderBasename}`, `${file}`, `${fileBasename}`, `${fileBasenameNoExtension}`, `${fileDirname}`, `${fileExtname}`, `${relativeFile}`, `${relativeFileDirname}`, `${cwd}`, `${lineNumber}`, `${selectedText}` (via active document if `INavigationService` resolvable), `${env:NAME}`, `${config:key}`, `${command:id}` (via `ICommandService`), `${input:id}` (`promptString`/`pickString`/`command` via `IWindowService`), `${pathSeparator}`/`${/}`, `${userHome}`, `${defaultBuildTask}` — applied recursively to every string in the config; platform-specific blocks (`windows`/`linux`/`osx`) merged; `CreateLaunchJsonAsync` writes an initial file from provider/contribution `initialConfigurations` (VS Code's template layout).
7. **netcoredbg for .NET** — `NetCoreDbgAdapterFactory` for `coreclr` (+ alias `netcoredbg`): locate binary in order `cscode.debug.netcoredbgPath` setting → `{ToolsDir}/netcoredbg/netcoredbg` → `PATH`; launched as `netcoredbg --interpreter=vscode`; if missing, offer (via `IWindowService`) to download the matching release from `https://github.com/Samsung/netcoredbg/releases` (linux-amd64/arm64, osx-arm64, win64; verify archive, extract safely against zip-slip, `chmod +x`) into `{ToolsDir}/netcoredbg` — progress via `WithProgressAsync`. Ship `tools/fetch-netcoredbg.sh` doing the same for tests/dev.
   Initial `coreclr` configuration template: `launch` of `${workspaceFolder}/bin/Debug/<tfm>/<Project>.dll` with `preLaunchTask: "build"` and a generated `tasks.json` `dotnet build` task; `justMyCode`, `stopAtEntry`, `env`, `args`, `cwd`, `console`, `sourceFileMap`, `symbolOptions`/`enableStepFiltering` passed through. Attach by `processId` (`${command:pickProcess}` implemented as a built-in command that lists processes via `IWindowService.ShowQuickPickAsync`).
8. **Tasks (minimum viable)** — additive Core contract `Core/Tasks/ITaskService.cs` (`RunAsync(taskLabel, folder, ct) → TaskResult{ExitCode,…}`, `GetTasksAsync`) and an implementation reading `tasks.json` (`shell` and `process` types, `command`, `args`, `options.cwd/env`, `dependsOn` (sequence/parallel), `group`, `${…}` substitution shared with launch variables), output streamed to an `IOutputService` channel `"Tasks"`, exit-code based success, cancellation kills the process tree; problem matchers can be ignored but must not crash on presence. `preLaunchTask`/`postDebugTask` use it. Register it in DI.
9. `AddCsCodeDap(this IServiceCollection)` registers `IDebugService`, `IBreakpointManager`, `IDebugConfigurationService`, `ITaskService` and the built-in adapter factories.

## SHOULD
* Data breakpoints, instruction breakpoints, `exceptionInfo` surfaced on the session, `loadedSources`, `modules` list model, `stepBack`/`reverseContinue` plumbing, `readMemory`.
* `attach` flow for `processId` + remote `host:port` server descriptors, `connect`/`serverReadyAction`-style "wait for port" helper.
* Debug-console `CompletionsAsync` with caching.

## Tests (`tests/CsCode.Dap.Tests`, xUnit v3)
1. **In-process fake adapter** (a scriptable server over pipes implementing a configurable subset): handshake order assertions, breakpoint sync (replace-all semantics, debounce), 1-based/0-based conversion with both settings, stop/continue/step event flows, variables paging + handle invalidation, evaluate contexts, reverse requests (`runInTerminal`, `startDebugging`), termination paths (graceful / adapter crash / timeout kill), multi-session. ≥ 60 tests.
2. **Real adapter integration** — `tools/fetch-netcoredbg.sh` fetches netcoredbg into `.scratch/tools/netcoredbg/`. The test writes a tiny C# console project into a temp dir (Program.cs with a loop, a method call chain, a local `int x`/`string s`, an exception path), `dotnet build`s it, then drives **IDebugService end-to-end**: set a breakpoint on a known line → launch → `Stopped(breakpoint)` at the right file/line → top frame name → locals contain `x` with correct value → step over/in/out change the line as expected → `EvaluateAsync("x + 1")` → conditional breakpoint & hit-count behave → logpoint output appears in Output → `ContinueAsync` runs to exit → `Terminated` with exit code → no `netcoredbg`/debuggee processes left. Skip with reason if the adapter or `dotnet` can't be obtained.
3. launch.json / variable substitution: golden tests (comments, trailing commas, compounds, platform blocks, nested substitution, unknown variable behaviour), tasks.json execution (real `sh -c`/`cmd` child), dependsOn ordering.
4. **Leak/soak**: start/stop 50 fake sessions (and 10 real ones if the adapter is present): no retained sessions/clients/handlers, thread + process + fd counts return to baseline, breakpoint manager holds no per-session state after termination.
